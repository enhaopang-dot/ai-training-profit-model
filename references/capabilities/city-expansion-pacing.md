# 城市扩展节奏框架（city-expansion-pacing）

## R — 原文规则

> "先跑通再扩张——前半年只做宁波+温州，流程跑通后才扩；每个新城市第一场必为免费沙龙/公开课，先打开当地企业圈层再做付费。"（组局官要求：本地人脉资源、AI 基本认知、组织能力、创业意愿）
> ——原文 §9 城市扩展策略（p56 城市扩展节奏规则 / f44 城市扩展节奏框架）

规则本体：两条节奏纪律——①先跑通再扩张：不同时在多城铺开，先在少数城市把流程跑通验证后再复制；②每城第一场必为免费沙龙/公开课：先打开当地企业圈层建立认知，再做付费转化。配套机制：新城市本地组织找"组局官"，按四要求筛选（本地人脉资源 / AI 基本认知 / 组织能力 / 创业意愿），物色渠道 = 公开课物色 / 客户推荐 / 目标城市商业社群。

## I — 释义

本框架管的是扩张的"时序"，不管扩张的"机制"。两条纪律分别防一种死法：先跑通再扩张，防的是"流程未固化就铺多城，交付 bug 被批量复制到新市场"（x25）；新城市首场免费，防的是"没认知基础就卖课，圈层没打开转化无从谈起"——免费首场是低风险的圈层破冰动作，不是亏损，买的是当地企业圈层的认知入口。

与 u17 组局官机制的分工：u17 管机制与分成（组局官负责什么、怎么分账），本卡管节奏（什么时候进新城、进去先做什么、按什么顺序铺开）。两者配套使用：组局官提供本地组织力，节奏纪律控制扩张风险。

适用前提：已在至少一个城市稳定交付、考虑进入新城市。不适用：首个城市的选择（归 u05 城市分层进入框架）；冷启动（归 u39）。

## A1 — 应用示例

- 正例 c22（亲历案例，§9 城市扩展策略）：作者的节奏控制——前半年只做宁波+温州两地，流程跑通后才向其他城市扩张；每进一个新城市，第一场活动必为免费沙龙/公开课，先打开当地企业圈层、建立认知，再做付费转化。结果：两年内扩展至 6 城市（杭州、温州、台州、金华、舟山、上海，作者自述）。
- 反例 x25（§9 城市扩展策略，bound 至本单元）：单城交付 SOP 还没固化就同时开多个城市，每城交付质量参差、组局官管理失控，口碑在异地被放大成品牌伤害。机制：城市扩张复制的是"已验证的交付流程+本地组局官网络"，不是 PPT 计划；流程未跑通时扩张 = 把 bug 批量复制到新市场。
- 反例 x24（§1/§2 城市选择，bound 至本单元）：没有品牌与案例积累的新团队直接打上海/深圳/杭州，跟几十个成熟讲师竞价拼资源，获客成本与信任门槛双高，迟迟开不了单。机制：实力不对等时选市场是比努力更大的变量——本条严格说属城市"选择"而非"节奏"，但与本框架直接衔接（先选对城市再谈节奏）。

## A2 — 触发场景

1. 在 A 市已稳定交付若干场，考虑进入 B 市，不知道什么节奏进。
2. 想同时在两三个城市铺开，被本卡纪律拦住，想知道为什么。
3. 进新城市的首场活动效果差，圈层没打开。
4. 在新城市找本地合作方（组局官），不知道按什么标准筛。

语言信号："什么时候去别的城市开""能不能两个城市同时做""新城市第一场办什么""组局官去哪找、怎么筛""扩张节奏怎么控制"。

英文 trigger patterns: "when to expand to a new city", "multi-city expansion pacing", "first event in a new market", "city expansion playbook", "regional partner selection criteria".

相邻区分：与 u17 组局官机制区分——u17 管机制与分成（组局官负责什么、按什么比例分账），本卡管扩张时序（先跑通再扩、首场免费）；与 u05 城市分层进入框架区分——u05 管"选哪个城市"（分层判断+四条件），本卡管"选定后按什么节奏进"；与 u43 模式决策区分——u43 决定用个人还是团队模式做这门生意，本卡默认模式已定、管地理扩张节奏。

## E — 执行契约

输入契约：当前城市交付状态（场次、SOP 是否固化）、目标城市、是否有本地组织资源。缺失"SOP 是否固化"必须先问——它是步骤 1 的前置条件，不可静默假设为已跑通。

步骤序列：

1. 确认前序条件：现有城市流程已跑通（"跑通"验收标准为自定约定——原文未给量化标准，可用：交付 SOP 成文 + 单场交付无重大翻车 + 有可参考的客户反馈）。若未跑通 → 停在原地固化流程，不进入步骤 2（判停点）。
2. 新城市破冰：第一场办免费沙龙/公开课，目标是打开当地企业圈层而非收入。完成标准：首场活动落地 + 当地企业圈层认知建立的可观察证据（加微数/社群数/邀约反馈，量级自定）。
3. 付费转化：圈层打开后再做付费单。完成标准：首场后 30 天内（时窗自定）有付费转化动作排期。
4. 本地组织：找组局官并按四要求筛选——本地人脉资源 / AI 基本认知 / 组织能力 / 创业意愿；物色渠道 = 公开课物色 / 客户推荐 / 目标城市商业社群。完成标准：候选人通过四要求核对表（每项有事实依据，非印象分）。

输出契约：扩张节奏计划（前序条件确认 + 破冰首场安排 + 付费转化时窗）+ 组局官筛选清单（四要求逐项核对表）。两者齐备才算扩张计划成型。

## B — 边界

- 反场景：首个城市选择归 u05；组局官机制与分成设计归 u17；冷启动路径归 u39；模式选择归 u43。
- 批判面（BOOK_OVERVIEW，verified gaps，必须如实告知用户）：宁波样本地域偏差——二三线蓝海与"先跑通再扩张"判断基于浙江城市带（制造业+跨境密集），对内陆城市产业结构适用性未验证，作者亦自认一线打法不同；"流程跑通"无验收标准（本卡 E 段给了自定约定，非原文规则）；"前半年只做两城"的时限是作者单样本节奏，非普适参数，须按自身现金流与组织能力重排。
- 失败模式（x25/x24 反向印证）：流程未跑通就铺多城 = bug 批量复制 + 口碑异地放大；没资源硬打一线 = 获客成本与信任门槛双高、迟迟开不了单。
- 相邻易混淆：与 u17 并用时先本卡定节奏、再 u17 定机制——顺序颠倒会导致"机制搭好了但时序错误"（多城同时铺 = 即使分成合理也会失控）。
