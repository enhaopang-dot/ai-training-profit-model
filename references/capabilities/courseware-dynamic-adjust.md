# 课件动态调整机制（u29）

## R — Rule（原文规则）

source_quotes：

> "学员对某模块感兴趣就多讲，冷淡就跳过。曾把以 Agent 框架为主线的课现场改成 AI 生图主线，满意度反而更高。灵活应变比死守大纲重要。"
> ——原文 §6.4 课件动态调整

> "每次重大工具发布……都激发一波培训需求；同时讲师门槛提高——不持续更新就会出现'客户比你更懂 AI'的尴尬。"
> ——原文 §2 AI 工具迭代的影响（长期轨动因，p07）

## I — Interpretation（自述）

课件不是交付前定稿就结束的资产，它在两个时间尺度上持续调整。**现场轨**：课堂上根据学员实时反应增减模块——感兴趣多讲、冷淡跳过，极端情况下可以改主线（作者亲历：把 Agent 主线课现场改成 AI 生图主线，满意度反而更高）。**长期轨**：工具/平台重大更新即更新对应课件模块，否则课堂会被学员的新工具认知问倒（"客户比你更懂 AI"）。总原则是"灵活应变比死守大纲重要"——大纲是课前基于问卷的假设，现场反馈才是真实需求；但灵活的前提是课前准备充分（双版本方案、摸底三问），应变是准备的延伸而不是准备的替代品。

## A1 — Application（应用示例）

**类型**：原书亲历案例（c17，绑定本单元）+ 原书反例（x11）。

**正例（c17，firsthand）**：
- 输入/问题：授课现场学员对 Agent 框架模块反应冷淡、对 AI 生图模块热烈；
- 方法执行：现场压缩 Agent 模块、扩 AI 生图模块，把课程主线整个改掉；
- 结论：满意度反而更高（作者自述）。长期侧同例：OpenClaw 发布后 Agent 内容大幅更新课件，避免课件过期。

**反例（x11，原文警告）**：把大纲当圣旨从头讲到尾，学员明显冷淡的模块照讲、低头玩手机仍继续——死守大纲等于放弃现场信息，满意度被拖垮。

## A2 — Activation（触发）

**典型情境**：
1. 课堂上某模块学员冷淡/热烈，纠结要不要切；
2. 主力工具发布重大版本，旧课件内容过时；
3. 学员用新工具把讲师问倒， credibility 受威胁；
4. 用户问"课件多久更新一次/现场要不要按大纲讲"。

**语言信号**："学员对这块没兴趣怎么办""要按大纲讲完吗""新工具出来了课件要不要改""课堂上能临时改内容吗"。

**英文 trigger patterns**：`adapt course on the fly`, `update courseware`, `students losing interest`, `course content outdated`, `flexible teaching`

**相邻区分**：
- vs u28（课件制作五步流程）：u28=交付前的静态生产流程；本卡=交付中与交付后的动态调整机制。
- vs u31（开场三问现场校准法）：u31 是开场校准信号源（三问摸底），本卡是贯穿全场的调整机制——三问给本卡提供第一次校准输入，之后靠全程观察。
- vs u42（心态四坑之"准备过度"）：准备要充分但不执着完美——u42 管"备课别过头"，本卡管"现场别僵死"，两者是同一枚硬币两面。

## E — Executable contract（执行契约）

**输入契约**（缺失应先询问）：
- 现场信号：学员反应（参与度/提问分布/练习完成情况）
- 或工具信号：课程涉及的工具近期是否有重大版本发布
- 可用备选：完整版+精简版方案是否已备（u30 第③件）——没有则现场调整空间受限

**步骤与完成标准**：
1. 识别信号——完成标准=明确写下触发事实（"X 模块练习完成率低于半数"或"Y 工具发布重大版本"）。
2. 选轨判断：现场反应→走现场轨；工具更新→走长期轨。
3. 现场轨执行：热模块扩、冷模块缩/跳；主线级调整有作者先例支撑（c17），但须确认剩余课时与必备内容不受影响——完成标准=调整后的大纲仍覆盖合同服务范围（接 u26 服务范围条款）。
4. 长期轨执行：工具重大版本→更新对应课件模块→在课件库记录更新时间与触发版本——完成标准=该模块内容与当前工具版本一致。
5. 沉淀：本次调整记录回课件库/知识库，下次同行业客户直接调用——完成标准=有沉淀条目。

**输出契约**：调整决策记录（改/不改+改哪个模块+幅度+理由）；长期轨另附课件更新时间戳。

## B — Boundary（边界）

**不适用场景**：
- 合同约定的必授核心内容（如客户付费指定的定制模块）——主线可换，合同范围不能丢；
- 政企等政治敏感场景的现场自由发挥——u36 红线优先于本卡灵活性。

**原书警告的失败模式**（x11）：死守大纲照本宣科；另一种失败是"灵活"变"随性"——调整幅度无原文边界，改到什么程度依赖讲师判断，无准备支撑的应变=裸奔。

**verified gaps**（shard2）：
- 调整幅度无边界（改主线可以，改到什么程度需讲师判断）；
- "准备充分是灵活前提"与 u42 准备过度坑需联动读；
- 长期轨的执行成本被低估——每次重大更新都要返工（时代局限）。

**BOOK_OVERVIEW 批判面**：
- 工具热点更替快（写于 2026-05，DeepSeek/OpenClaw 热潮后），长期轨实际是持续现金流出的维护成本，单人讲师需评估自己能否跟上更新节拍；
- "灵活应变>死守大纲"的判断基于作者 20-50 人线下场互动密度，线上大班/录播课现场信号弱，调整空间天然受限。
