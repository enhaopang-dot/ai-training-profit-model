# 自用系统"脱壳"产品化流程（u12 · cap.ai-training-profit-model.deshell-productization）

## R — Reading（原文）

- 「把团队内部用的 Obsidian 知识库系统…'脱壳'成通用版 Vault 对外售卖——清掉个人内容，保留框架、模板、流程、SOP。」（f10，第三章「从自用工具到标准化产品」，原文 L120-130）

## I — Interpretation（自述）

把团队自用的系统/工具转成对外标准产品，固定四步：①清掉个人内容与私有数据（账号数据、私人文件、客户痕迹）；②保留框架、模板、流程、SOP——这是可迁移的资产；③包装成通用版产品（可作引流款）；④衍生行业定制版＋陪跑（产品交付＋1 次培训＋3 个月答疑陪跑）。价值两条：边际成本近零的第二收入曲线（三层漏斗第二层"标准化产品=规模收入"）；同时反向强化"我们自己就在用"的信任（供给漏斗顶层）。适用前提：手里有真实自用的系统，不为产品化而临时造一个。

## A1 — Application（正反示范）

- 正例（c06，作者亲历，bound 到本单元）：团队把内部 Obsidian 知识库系统（配合 Claude Code 与 Hermes Agent）清掉个人内容、保留框架/模板/流程/SOP，做成"AI 数字员工操作系统"，形成产品矩阵：通用版 Vault 骨架（引流）→OPC 内容自动化营（1 天实操课）→AI 获客 Agent 实操营（2 天实操课）→行业定制版 Vault＋陪跑。形成可规模售卖的产品线（作者自述，未给销售额）。
- 反例（合成演练，标注"原书未提供脱壳失败案例"，按 shard1 walkthrough 复算）：输入=讲师自用的小红书文案生产 SOP（提示词库＋流程文档＋账号矩阵管理表，含个人账号数据）。四步走：①清掉个人账号数据与私有文案→②保留框架（选题→生成→审核→发布）/模板/提示词结构/SOP→③包装"小红书 AI 文案系统"通用版做引流款→④衍生行业定制版（美妆/家居垂类）＋1 次培训＋3 个月答疑陪跑（原文行业定制版口径）。"删私有、留框架"边界原文口径明确，可复算。

## A2 — Future Trigger

1. 典型情境：①团队自用了一套系统（知识库/工作流/Agent），想把它变成可卖的产品；②想设计引流款＋训练营＋陪跑的产品矩阵；③想把服务经验沉淀成标准化交付物；④纠结产品化从哪开始。
2. 语言信号（中文触发词）："我们自己在用的系统能卖吗""怎么把内部工具变成产品""脱壳怎么做""引流款和标准版怎么搭配""自用系统怎么产品化"。英文 trigger patterns: "productize internal tool", "de-shell own system for sale", "turn in-house workflow into product", "standard product from self-use"。
3. 相邻区分（初稿）：与客户定制开发（一次性项目，见 u44 延伸服务）不同——脱壳是"一次清理、多次售卖"的标准品；与 u07 产品四层不同——本卡是其中"标准化产品"层的产出动作；工具链不同（非 Obsidian＋Claude Code 时"保留什么清掉什么"的边界须自定）。

## E — Execution（可执行步骤）

输入契约：必需=自用系统描述（构成清单：框架/模板/流程/SOP/个人内容各自位置）；可选=目标行业（用于第四步定制版）。缺系统清单时先让用户罗列，不假设内容。
步骤：
1. 脱壳清理：列出"删什么"清单——个人账号数据、私有文案、客户痕迹、不可迁移的环境配置；逐条删除。
2. 保留确认：列出"留什么"清单——框架、模板、流程、SOP，确认不含任何个人/客户私有内容。
3. 包装通用版：命名（建议体现"系统/操作系统"定位）＋整理成可交付包，可作引流款。
4. 衍生定制版：行业定制版＋1 次培训＋3 个月答疑陪跑，形成产品矩阵。
输出契约：脱壳清单（删什么/留什么，逐项打勾）＋通用版产品包结构＋定制版衍生方案（行业/服务组合）。

## B — Boundary（边界）

- 反场景：没有自用系统时不适用（不为产品化而造系统）；不是客户定制开发流程；清理不彻底（残留个人数据）会出隐私与信任事故，禁止交付。
- 失败模式：删留边界不清——把个人经验当框架卖（客户复现不了），或把框架也删掉只剩空壳；通用版与定制版定价无梯度（原文未给定价指引）。
- verified.md 的 gaps：①原文实例特定于 Obsidian＋Claude Code 工具链，迁移到其他系统时"保留什么清掉什么"的具体边界需从业者自定；②无定价指引（引流款免费/低价与定制版收费的梯度原文未给）。
- 批判面（BOOK_OVERVIEW）：工具链时效——原文工具名（Claude Code、Hermes Agent）随迭代可能过期，脱壳产品的"我们自己就在用"说服力依赖工具链不过时。
