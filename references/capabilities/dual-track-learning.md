# 双轨学习法（dual-track-learning）

## R — 原文规则

> "技术端：订阅 AI 资讯……每周几小时测试新工具；没时间就让 AI 助理看 GitHub 近期 star 增长最快的项目……业务端：每做完一个行业培训就复盘沉淀该行业 AI 应用场景库，下次同行业客户直接调用。实战端：最好的学习是教。"
> ——原文 §8 双轨学习法（p50 / f39 双轨学习法）

规则本体：三条学习线并行——技术端（订阅资讯/关注博主/每周几小时实测新工具；时间不够时让 AI 助理盯 GitHub star 增长榜；重点盯能用于企业场景的变化；沉淀进 Obsidian 知识库）、业务端（每做完一个行业培训就复盘沉淀该行业 AI 应用场景库，同行业客户直接调用）、实战端（以教促学，学员提问反过来推动研究，交付即学习闭环）。

## I — 释义

本方法是对冲"知识半衰期短 / 客户比你更懂 AI"（x15）的唯一机制性解法，也是本书批判面（时代局限：工具链快速过期）对讲师侧的正面回应。三条线的逻辑各不相同：技术端是防御——保持"懂 AI"的入场券持续有效；业务端是进攻——把每一场交付变成可复用的行业资产，同行业下一单直接调用，摊薄 u27 模块化课件的定制成本；实战端是闭环——学员的提问是最好的研究选题库，交付本身产出新知识。

一个命名与结构不一致的原文事实必须保留："双轨"实际包含三端（技术/业务/实战），原文如此，本卡照实呈现，不擅自改名也不擅自合并。

适用前提：在职讲师的日常学习机制设计。不适用：一次性考前冲刺（本方法是常驻机制不是冲刺计划）；也不解决"要不要学"的心态问题（归 u42）。

## A1 — 应用示例

本单元无绑定亲历正例（支撑材料仅 x15 反例），按"最贴近者"原则示范：

- 反例 x15（§2 AI工具迭代的影响 + §8 双轨学习法，bound 至本单元）：讲师靠几门存量课件吃老本，不跟进新工具新版本；课堂上被学员用新工具问倒，"专业可信"人设当场崩塌，复购与转介绍清零。机制：AI 工具迭代快，知识半衰期极短，供给四层漏斗第一层"懂 AI"需要持续续费。对照执行：x15 的失败正是三端全部缺位——技术端停更（被问倒）、业务端无沉淀（每单从零备课）、实战端无闭环（学员提问未转成研究课题）。
- 正例侧原文未给独立案例：p50 以规则形态直接给出三端动作（含"AI 助理看 GitHub star 增长榜"这一降时耗替代动作），无亲历数据交代，如实标注。

## A2 — 触发场景

1. 感觉 AI 工具更新太快跟不上，担心课堂上被学员问倒。
2. 每接一个行业的新客户都从零开始备课，成本居高不下。
3. 课闲期（无排期）不知道日常该做什么维持竞争力。
4. 学员课上提的问题自己答不上来，想把它变成研究输入。

语言信号："AI 更新太快怎么跟上""讲师平时怎么学习""备课成本太高怎么降""怎么保持竞争力不被淘汰""学员问倒我了怎么办"。

英文 trigger patterns: "continuous learning for AI trainers", "knowledge decay half-life", "how to keep up with AI tools", "industry case library reuse", "learn by teaching loop".

相邻区分：与 u40 讲师四项能力区分——u40 管四格能力定位（含"要不要做讲师"的决策），本卡管第一格能力的日常续费机制；与 u42 心态四坑区分——本卡是行为机制，不管心态重构。

## E — 执行契约

输入契约：当前排期状态（本周/本月有无交付）、可投入学习时间（每周几小时，真实数字）、现有沉淀工具（是否有 Obsidian 或等价知识库）。缺失"每周可投入时间"应先询问，不可静默假设。

三端动作清单：

1. 技术端：本周安排几小时实测新工具（时长自定，原文"每周几小时"未量化）；时间不足时启动替代动作——让 AI 助理看 GitHub 近期 star 增长最快项目；只记录能直接用于企业场景的变化。完成标准：Obsidian 知识库新增 ≥1 条可用条目（工具名/适用场景/实操结论）。
2. 业务端：复盘最近一场行业培训，产出该行业 AI 应用场景库条目（场景/痛点/方案/可复用提示词）。完成标准：场景库条目存在且下次同行业客户可直接调用。
3. 实战端：把学员课堂提出的未解问题转成研究课题，产出新方案或知识库条目，反哺下一场交付。完成标准：每个未解问题有"已研究/排期中/已答复"三态之一。

输出契约：三端动作清单（各端本周动作 + 完成状态）+ 两项沉淀物（知识库条目 / 行业场景库条目）。三端齐备才算学习闭环成型。

## B — 边界

- 反场景：一次性冲刺备考不归本卡；心态问题（怕学员更懂/焦虑）归 u42；能力定位决策归 u40。
- 原文缺口（verified gaps）：命名"双轨"实含三端（技术/业务/实战），命名与结构不一致（原文如此，照实保留）；"每周几小时"未量化，须自定真实时长；对兼职讲师的时间约束原文未讨论——兼职者执行本卡时三端需降频而非全砍，具体降法自定。
- 失败模式（x15 反向印证）：三端全缺的最坏结果不是"落后"，而是"专业可信"人设当场崩塌——B 端采购的信任前提被击穿。
- 相邻易混淆：u27 课程体系模块化是业务端沉淀的消费方——本卡产出的行业场景库喂给 u27 的"定制三调整"，两卡是生产-消费关系。
